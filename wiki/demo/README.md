# Fieldnote

A small home for working notes: the questions a person carries around, the
half-formed ideas they keep returning to, and the small decisions that turn a
note into something usable. Fieldnote is built for one person first; sharing
is a later concern.

This repository is the demo product: its documents are written in the skill
set's forms, one document of each kind, linked into one chain — the vision,
a source, a hypothesis, a user story, a use case, product requirements, an
open question, a prototype and its result, a practice, and the project's own
records (a milestone charter, a decision, a design, a change record, an
exploration note, the architecture and a capability document).

Start with [the vision](docs/vision.md). The one document written to fail
the set's check stands at
[docs/requirements/FR-999-a-failing-example.md](docs/requirements/FR-999-a-failing-example.md):
its page shows the check's findings where the reader reads.
