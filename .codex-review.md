# Review: feature/madarch-graph-connected — madarch-m38l.16

Reviewed `git diff origin/main...HEAD`, HEAD `d64e509b4c1d0f1cd47b3c4a4239547772923a6f`, against origin/main `56de74087ec245c4d85a232dec198f045a527c9e`. Static review only: no `bun test`, `tsc`, build, or browser execution. The pre-existing working-tree change to `docs/changes/madarch-m38l.16/change.md` was excluded. Findings below are correctness or coverage defects, not matters of taste.

1. **[P1] Multiple alterations of one table stop the fill.** `src/extract/data-model/extract.ts:541` (also :544; edge identity assigned at :525). A migration containing `ALTER TABLE orders ADD COLUMN a TEXT; ALTER TABLE orders ADD COLUMN b TEXT;` emits two `code.alters` edges with the same migration, table and empty discriminator. Different spans do not distinguish ordinary edges: `src/extract/driver/index.ts:630` throws on the duplicate. A normal migration therefore prevents the graph fill from completing and readers from receiving its pages. **Smallest fix:** deduplicate the migration-to-table relation by logical identity; retain the distinct column edges. If separate statement edges are intended, use a stable statement discriminator instead.

2. **[P2] The added ALTER regression test cannot detect that failure.** `test/extract-data-model.test.ts:166`. The filter requires the part after `code.table:` to contain no slash, but every table key is `code.table:<database>/<schema>.<table>` (`src/extract/data-model/keys.ts:39`). Thus `tableEdges` is empty, uniqueness compares zero with zero, and `every()` returns true. Duplicate table edges in finding 1 pass both assertions. **Smallest fix:** identify table targets by their declared node kind (or require exactly one slash), assert a nonempty selection, and include two alterations of the same table in one migration.

3. **[P2] Entry-point edges invent services and unverified processes.** `src/extract/contracts/index.ts:315` and :317 (TypeScript equivalents :420 and :422). `serviceOf` at :199 falls back to the entire file path, so a Go main at `cmd/tool/main.go` acquires a `belongs-to` edge to `code.service:cmd/tool/main.go`, although the service extractor only declares services with manifests under `services/`. Likewise `processKeyOf` guesses a process without checking whether deployment extraction declares it. The driver materializes these ends as reference nodes, so readers see a fabricated service and potentially an extra, disconnected-from-deployment process instead of a factual startup chain. **Smallest fix:** make service lookup return undefined outside a declared service, and resolve process/service edges against nodes actually declared by the owning extraction; otherwise keep the entry-file link.

4. **[P2] Tab-containing paths silently lose their line counts.** `src/extract/history/git.ts:278`. `--numstat -z` leaves tabs inside an ordinary filename intact. For `1\t0\tdir/a\tb.txt`, destructuring `split('\t')` stores the count under `dir/a` rather than `dir/a\tb.txt`. The touched edge then has no counts, and the commit page explains the text file as binary; another real `dir/a` entry can also be overwritten. **Smallest fix:** split only the first two tabs and preserve the remaining path bytes. Validate counts as either two decimal values or the exact binary pair `-`/`-`: :285 and :289 currently silently drop every other count pair instead of naming a failed parse.

5. **[P2] Author file statistics silently truncate and conceal their total.** `src/knowledge/history.ts:101` and :129. Each commit is limited to 500 touched files, but `touched.total` is ignored. An author with one 501-file commit gets incomplete file rankings and churn without any warning, since the only warning at :126 checks the number of commits. The top-file slice also reports `total: topRows.length`, so an author touching 30 files appears to have a complete ten-file result. **Smallest fix:** report every per-commit cut as structured data, explicitly describe rankings over a partial sample, and set the file section total to the number of aggregated distinct files before slicing.

6. **[P2] Russian history pages print English product prose.** `src/knowledge/history.ts:59`, :82–86 and :126; rendered verbatim at `wiki/app/src/knowledge/blocks.tsx:544`. A Russian page for a binary change, merge, large task or prolific author prints English explanatory notes under translated headings. These are generated UI strings, not repository content; matching column and figure locale keys do not translate them. **Smallest fix:** return typed note keys with numeric/path arguments and render them through keys supplied in both `wiki/app/src/locales/en.json` and `ru.json`.

7. **[P2] Missing counts are falsely diagnosed as binary, and empty commits as merges.** `src/knowledge/history.ts:85` and :86. A text-file rename produces touched edges for both the old and new paths (`src/extract/history/files.ts:63`), while numstat deliberately counts only the destination. The old path therefore triggers the assertion that a file has no counts because it is binary. Separately, a non-merge commit created with `--allow-empty` has no touched edges and is described as a merge. **Smallest fix:** use neutral missing-count text unless an explicit binary flag is stored, and consult the commit's stored merge flag before claiming it is a merge.

8. **[P2] Module-cycle source links point to directories.** `src/extract/code/index.ts:572`. When `emitCycles('module', moduleGraph)` runs at :577, its member keys contain module folders. Removing the kind prefix and using the remainder as a span path produces, for example, `services/orders/src/domain` as a file location. Readers following the cycle's location cannot open source bytes at that directory. **Smallest fix:** reuse the selected module node's actual member-file span, rather than deriving a file path from a module key.

9. **[P2] Definition counts include members that the table never renders.** `src/knowledge/definition.ts:32–35` and :62–75. AsyncAPI extraction declares both channels and messages (`src/extract/contracts/index.ts:138–142`), but `membersOf` only emits rows for operations and channels. For 200 channels each carrying two distinct messages, the graph has 600 declarations. The 500-row declaration cap gives a notice saying “Showing 500 of 600 contract members” above a table containing only the 200 channel rows (channel keys sort before message keys). Messages also consume the declaration limit despite having their own separate channel query. **Smallest fix:** count and limit the renderable member kinds consistently; keep message counts in the channel's detail totals/cut notices.

10. **[P2] Distinct valid operations can receive identical HTML IDs and React keys.** `src/knowledge/definition.ts:25` and :54; used at `wiki/app/src/knowledge/blocks.tsx:574`. Without operationIds, `GET /pets/{id}` and `GET /pets/-id-` both sanitize to `op-GET:/pets/-id-`. Both operations are valid, but fragment navigation cannot address the second row reliably, and React sees duplicate keys. Non-ASCII channel names have the same lossy conversion problem. **Smallest fix:** derive anchors from an injective encoding of the member's logical identity, or append a deterministic identity digest.

11. **[P2] The exhaustive placement audit accepts invalid source locations.** `test/extract-driver-suite.ts:262`. It only checks that the path is a string and the line bounds are numbers. The directory-valued module-cycle span in finding 8 passes, as do nonexistent paths and inverted or out-of-range lines. Consequently the committed audit's “placed” result does not protect readers from broken source links. **Smallest fix:** for nodes declared in the pinned tree, verify that the span names a blob and that its line/byte bounds fit that blob; explicitly validate historical-only locations against their source revision instead of broadly exempting them.

12. **[P2] The parity test exempts one-hop relations from depth-enabled blocks.** `test/knowledge-vertical.test.ts:496`. The depth branch of `relatedBlock` assigns `hops` to every returned row, including direct neighbors with `hops: 1` (`src/knowledge/blocks.ts:252`). Skipping every defined value therefore hides missing direct edges whenever a page's `related` block uses depth. The remaining global `rows > 0` assertion can be satisfied by unrelated pages, and an unrelated neighborhood edge defeats the empty-neighborhood check. **Smallest fix:** skip only rows with `hops > 1` and exercise a depth-enabled block with both direct and indirect neighbors.
