# Publish templates before a repository is filled

Change: madarch-64o5.29
Base: 0148a638fa234accc37a871416f954d4ae3bcf15
Tasks: madarch-64o5.29
Kind: behavior

## Intent
File, folder and repository pages must work after filling only Files. Templates
are product declarations, not content generated by a Fill.

## Rationale
Startup previously published catalogue metadata while leaving template opinions
for an agent fill. A Files-only fill therefore produced entities whose pages
failed with `expected one structured template opinion, found 0`.
No owner approval is recorded by this change.

## Out of scope
- New UI components or changes to the wiki app.
- Real agent or model runs.
- Acceptance or closure of the task.

## Changes to requirements
- product-wiki/startup-templates: validate and publish templates with the startup catalogue; refresh valid edits and retain the last valid publication on errors.

Complete proposed capability: `capabilities/product-wiki.md`.

## Preserved contracts
- product-wiki/catalog: catalogue metadata remains declaration data, not evidence of a successful Fill.
- product-wiki/pages: readers consume graph opinions, not a second product-file interpretation path.

## Coverage
- product-wiki/startup-templates: test, static, mutation, review
- product-wiki/catalog: test
- product-wiki/pages: test

## Where it is seen
Kind: command
Place: startup, the running wiki's file, folder and repository pages, and template edit diagnostics

1. Initialize a fixture product and connect a small fixture repository.
2. Start the server and fill only Files, with no agent/model invocation.
3. Open a file, folder and repository page: each renders its declared blocks.
4. Save a valid template edit: its new structured opinion appears without Fill.
5. Save an invalid edit: diagnostics name its full path and line; the previous valid page remains.
6. Start with an invalid referenced template: startup refuses before serving readers.

## Blocking questions
None.
