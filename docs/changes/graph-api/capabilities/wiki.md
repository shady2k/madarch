# Wiki

Capability: wiki

## Purpose
A product's wiki is its knowledge graph, read through one API (capability graph-queries) and shown as pages composed from
the product's templates in the browser (decision 0036). The static site the earlier capability built — one page per
model element generated by Zensical or Starlight — is gone with the model store it read; no build writes pages, and the
server renders none.

## Requirement: pages — A page is a template over the graph
Every entity of the product's graph shall have a page address: `/` for the home, `/e/kind/id` for every entity,
`/p/template with the name=value query parameters` for a template bound to no entity. A page's sections shall be the sections of the
template it is given, composed into one GraphQL operation and run in the browser; the page's data shall come from that
operation alone, and no server module shall name a kind, hold a query or build a block. The addresses the app answers are
answered by the app shell until the template frontend lands; every other read address the page layer had answers 404.

### Scenario: entity-addresses
- Given: a served product
- When: `/e/kind/id` and `/kind/kind.md` are asked
- Then: the entity address answers the app shell as HTML and the Markdown kind address answers 404
  Checked by test/removed-routes.test.ts

### Scenario: no-server-page
- Given: the server's modules
- When: the architecture check runs
- Then: no module outside the catalogue data names a kind, and no route outside `/graphql`, `/graphql/schema` and the retained commands answers a read
  Checked by scripts/check-architecture.ts (`graphql-only-reads`, `no-kind-names`)

## Requirement: templates — The product's templates are its pages
A page's template shall be a file of the product under `templates/`, named by its relative path without its extension and
listed by `bootstrap`; the template an entity opens with shall be its own, else the template its catalogue record names,
else the base `entity`, and the base templates the starter ships shall be `home`, `entity` and `text`. A template naming an
unknown component or parameter shall be refused at start with its file and line. The Liquid templates, their compiler and
the structured `template` kind shall be deleted: no server module interprets a product's page syntax.

### Scenario: templates-listed
- Given: a served product holding a file under `templates/`
- When: `bootstrap` is queried
- Then: the template is listed by its name and its body, and an entity's `template` names the template it opens with
  Checked by test/graphql-schema-route.test.ts

### Scenario: liquid-gone
- Given: the repository's catalogue and starter set
- When: a product is created from the starter set
- Then: no `templates/*.liquid` file is written, no kind declaration names a `template:`, and the starter schema holds no `Template` type
  Checked by test/knowledge-parse.test.ts and test/graphql-starter.test.ts

## Requirement: export — The page's Markdown is the frontend's
The Markdown export of a page shall be produced by the frontend from the sections it drew, not by the server; the server
shall answer no page file, no kind file and no `/llms.txt`, and an address for any of them answers 404.

### Scenario: no-server-export
- Given: a served product
- When: a page's `.md` and `.json` addresses and `/llms.txt` are asked
- Then: each answers 404
  Checked by test/removed-routes.test.ts

## Requirement: result — Served or refused, and why
A wiki shall be served by the server a local madarch runs (capability product-wiki), from the app's built files; when the
app's files cannot be built the command shall exit 2 printing what the builder said and serve nothing. A request the
server cannot answer shall name what was asked for.

### Scenario: build-failure-refuses
- Given: an app folder whose build fails
- When: madarch serves a product
- Then: it exits 2 with the builder's words and serves nothing
  Checked by test/product-serve.test.ts

## Quality requirements
- A page answers in under 1 s warm on madarch's own product; one request per page view.
- Offline reopening shows the last cached answer with the revision it was read at (the frontend's cache, landing with it).

## Context
Decision 0036, sections 6 and 7; decisions 0018 (madarch's own app) and 0031 (one page in layers).

## Coverage limits
The template frontend is the next change: until it lands the app answers its addresses with the shell, and no component
renders a section.
