# A product made by an earlier madarch is brought to the current starter set, one bad kind never blocks the index, and product settings hold the agent, model, language and the two local resets

Change: madarch-m38l.11
Base: 05af1efa4ccd3b72531c9f0c93fea0dd8d260982
Tasks: madarch-m38l.11
Kind: behavior

## Intent
The owner's walk of 0.2.2 on 2026-10-23 found four faults that share one cause: the manifest and the templates are the product's own files, so a product made by madarch 0.1.x or 0.2.0 kept its old kinds for ever. Everything fell into «Прочее», a use case was not an entity, the roles changed nothing, there were no contracts and no route links, and two manifest lines made the index refuse all five written pages and twenty-one questions. This change brings such a product to the current starter set where no person edited the files, offers the rest item by item, makes the index drop only what a finding is scoped to, tells failures once in the reader's language, and gives the product a settings page, reached from the bottom of the sidebar, that holds the agent, the model and reasoning level the agent reports over ACP, the page language, the writer's bounds and the two local resets.

## Out of scope
- Merging the current templates into a template a person edited: only the manifest's missing items are offered; an edited template is never rewritten and is not offered new blocks.
- Committing the upgrade in the product repository: the silent upgrade changes files on this machine, like the pages the agent writes, and records what it wrote in the machine's state.
- A list of models inside madarch (the owner: «можно ли пользователю дать выбрать модель у harness?»): the agent names them.
- Real agent runs: the model query is checked against the ACP fixture agent only.
- The reader-shell files another worker owns (tabs, statement click, sources page, ground cards) and `src/writer/*` beyond one option.

## Design and decisions
- Who wrote a file (`src/knowledge/starter-upgrade.ts`). A starter file is madarch's alone when it is exactly what the current set holds; or its content hash is one this machine recorded when madarch wrote it (`<knowledge root>/<product id>/starter.json`); or git tracks it, every commit that touched it has the subject `Create the draft product`, and the working copy is the committed text or, for the manifest, the committed text with the two additions madarch itself makes (the page language, the question and correction kinds) regenerated by the YAML library to the byte. Anything else, including a comment added and not committed and a file git does not track, is a person's. The manifest an «Add» wrote is never recorded: a person's file with items added stays a person's file. A file that is a link is never written through.
- What is brought up, and when. The first read of the manifest by a `KnowledgeProduct` runs `upgradeStarterSet`: a madarch-only manifest is replaced by the current starter set with the product's `language:`, madarch-only templates are replaced, absent templates are written, a person's files are left and `kept` names them. `startFill` still runs `ensureLoopKinds` for an edited manifest, which now writes the question and correction kinds with no `group` when the manifest does not declare it (it wrote `group: product` into a manifest with no `groups:`, so both kinds became findings).
- What is offered. For a manifest left as a person's, `starterOffers` lists a group some kind names and the manifest does not declare, the roles (one item, or per missing role), the document exclusions, every starter kind the manifest lacks, and the missing `group`, `labels`, `description` or `origin` of a kind it has. The Problems page shows them with «Добавить» each and «Добавить всё»; `addStarterItems` edits the YAML document, so comments and the rest survive, adds the group a kind or a role needs, and writes the template a kind needs. The navigation's Problems count includes only open problems, never starter offers.
- The index (`src/knowledge/index/index.ts`). A finding scoped to a kind's declaration or to a page leaves out that kind or that page; `indexProductMarkdown` answers the findings, the fill worker tells them once on standard error, and the Problems page lists them with file and line. Only a manifest that cannot be read at all (`KindsManifest.unreadable`: not YAML, not a mapping, no `kinds` mapping) publishes nothing, because an index made from no kinds would unpublish every page the graph holds.
- Errors. The fill and the writer send a `code` beside the English `message`; the app words the code in the reader's language (`errors.fill.*`, `errors.writer.*`), keeps the message behind "Details for an engineer" and links the Problems page. A code the app has no words for shows the message. The manifest's findings on the overview use the same box (`Findings` with `scope="manifest"`). The fill's card is drawn only above the product's page and an entity's page.
- The model and the reasoning level. `session/new` reports `configOptions` (categories `model` and `thought_level`) or, in the protocol's earlier form, `models`; `src/fill/acp-choices.ts` reads them, `queryAgentChoices` starts the adapter, opens one session with no tools, sends no prompt and stops. Nothing is a list in madarch. A choice is saved in `writer.json` beside the agent, refused when the agent does not report the value, dropped when another agent is chosen, and set on each session (`acpUnitAgent` option `preferences`) only when the agent still offers it, each time from the state the agent last answered, because choosing a model can move the level. The query is cached five minutes, shared between asks that arrive together, and answers only a request from the wiki's own page.
- The two resets. «Переписать страницы» removes the pages with `producer: agent` and keeps the graph and every page a person wrote, then starts a fill with the chosen agent. «Начать с нуля» does what `madarch reset` does (pages and graph), puts the manifest and every template at the current starter set (the page language kept) and starts a fresh fill. Both are refused while a fill runs. The confirmation names the files, says the action is local, says a page the agent wrote and a person edited in place goes too (its front matter still says the agent wrote it), and lists the starter files a person edited that the reset replaces. The product selector no longer offers a start over.
- Is anything pushed? No. `git push` appears in the code only in `src/product/discussion-writer.ts`, the library function `answerProductQuestion` that `src/index.ts` exports; no route, command or fill calls it. The wiki's answers and corrections commit locally, the pages the agent writes are not committed, and the resets change files in the checkout and the derived store on this machine. The settings page says so.
- A change of the page language records the language the pages are in first when no record of it exists, so the next refresh sees the change and writes the pages again.
